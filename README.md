# Harx — النشر على استضافة مجانية (Supabase + Cloudflare Pages)

## الخطوات (حوالي 20 دقيقة)
1. **Supabase:** اعمل حساب مجاني على supabase.com ← New project (اختار منطقة في أوروبا) ← احفظ كلمة سر القاعدة.
2. **القاعدة:** افتح SQL Editor ← الصق محتوى `supabase.sql` كله ← Run. لازم يخلص بدون أخطاء.
3. **المفاتيح:** Project Settings ← API. انسخ **Project URL** و**anon public key**. افتح `index.html` بأي محرر نصوص وابحث عن `PASTE_SUPABASE_URL` و`PASTE_ANON_KEY` وحط القيمتين مكانهم.
   - ⚠️ حط الـ anon key بس. ممنوع تحط `service_role` في أي ملف.
4. **الإيميل:** Authentication ← Providers ← Email. لو مش عايز تأكيد بالإيميل وقت التجربة اقفل Confirm email (والأفضل تسيبه مفتوح بعدين).
5. **الرفع:** Cloudflare Pages ← Create ← Direct Upload ← ارفع مجلد فيه `index.html` فقط. هيدّيك رابط. (بدائل مجانية: Netlify Drop أو GitHub Pages.)
6. **أول دخول:** افتح الرابط وسجّل حسابك **أنت أولاً**: أول حساب بيبقى المالك تلقائياً. بعدها Authentication ← URL Configuration ← حط رابط موقعك في Site URL.
7. **الموظفين:** من تبويب «الموظفين» (للمالك) اكتب اسم الموظف وإيميله وكلمة سر مؤقتة ودوره واضغط «إنشاء الحساب». سلّمه البيانات وهيدخل من نفس الرابط. لو طلب تأكيد إيميل اقفل Confirm email من Authentication ← Providers ← Email. نسيان كلمة السر: Authentication ← Users في Supabase.

## اللي اتحل
- مفيش حد أقصى 500 فاتورة (بيتحمّل كل شيء على دفعات).
- زر **نسخة احتياطية** (للمالك فقط، أعلى الشاشة) بينزّل ملف JSON بكل البيانات. اعمله أسبوعياً وخزّنه برا.
- لو موظفين سجّلوا دفعات على نفس الفاتورة في نفس اللحظة: الدفعتين بيتحفظوا. وقاعدة البيانات بترفض مجموع دفعات أكبر من الإجمالي.
- أي حساب جديد مفيش له وصول لحد ما المالك يفعّله (محمي من القاعدة نفسها).

## حدود لازم تعرفها
- Supabase المجاني بيوقف المشروع بعد حوالي أسبوع بدون استخدام. لو المحل هيتقفل مدة، ادخل المشروع من لوحة Supabase وفعّله بعدين. راجع حدود الخطة الحالية على موقعهم لأنها بتتغير.
- إخفاء الأسعار والأرباح عن الاستقبال والفني بيتم في الواجهة. القاعدة بتمنع غير المسجّلين وبتخلّي «مشاهدة فقط» قراءة بس، لكن موظف تقني مفعّل ممكن يوصل للبيانات. فعّل بس اللي تثق فيهم.
- بيانات النسخة اللي على claude.ai مش هتنتقل لوحدها.
- لسه ما اتعملش: إخفاء الأسعار عن الفني والاستقبال على مستوى قاعدة البيانات (دلوقتي بيتخفوا من الواجهة بس).

## تحديث (لو كنت شغّلت supabase.sql قبل كده)
شغّل `supabase.sql` تاني كامل في SQL Editor: آمن ومش هيمسح بيانات. الجديد: ترقيم الفواتير H-00001 وما بعده تسلسلي بدون فجوات من السيرفر، وبعد ما اتسجّل مبيتغيّرش.

## جديد في الواجهة
- زر «تعديل» للفاتورة (مالك/مدير): الاسم، الموبايل، اللوحة، الأسعار، الخصم. مش بيسمح بإجمالي أقل من المدفوع، وكل تعديل بيتسجّل.
- إلغاء فاتورة عليها دفعات بيسجّل استرداد تلقائي بنفس المبلغ ويتخصم من «المحصّل».
- أزرار الفاتورة بتظهر حسب دور الموظف (الفني ميشوفش الأسعار ولا الدفعات).

## تحديث الحماية والصيانة (شغّل supabase.sql تاني كامل + ارفع index.html الجديد)
- **الصلاحيات من القاعدة:** الاستقبال يسجّل دفعات فقط، والفني يغيّر الحالة فقط، والإلغاء للمالك فقط. أي محاولة غير كده القاعدة نفسها بترفضها حتى لو حد عدّل الواجهة. (الفني والاستقبال لسه *بيقدروا يقرأوا* الأسعار تقنياً.)
- **منع تضارب التعديل:** لو جهازين عدّلوا نفس الفاتورة في نفس اللحظة، التاني بتظهرله رسالة «اتعدّلت من جهاز تاني» بدل ما يمسح تعديل الأول.
- **نسيت كلمة السر:** رابط في شاشة الدخول بيبعت إيميل لتغييرها. (إيميلات Supabase الافتراضية محدودة العدد في الساعة. راجع الحدود عندهم.)
- **الاسترداد:** بيتسجّل بنفس طريقة دفع كل دفعة (كارت يرجع كارت، إنستاباي يرجع إنستاباي).
- **نسخ احتياطي أسبوعي تلقائي + منع إيقاف المشروع:** ملف `github_workflow/harx-maintenance.yml`. مستودع GitHub خاص + 3 أسرار (الشرح داخل الملف). غير مجرّب، ولو فشل pg_dump بسبب اختلاف الإصدار ابعتلي الخطأ. GitHub بيوقف الجدولة لو المستودع ما اتلمسش 60 يوم، فادخله وشغّله يدوي من وقت للتاني.

## تحديث: ملف جاهز للرفع (من الموبايل)
- `index.html` فيه Project URL و anon key لمشروعك بالفعل، من غير ما تعدّل أي حاجة. ارفعه على GitHub بدل القديم كما هو.
- بعد الرفع افتح الموقع في **تبويب خاص** (أو امسح الكاش) عشان المتصفح ما يعرضش النسخة القديمة.
- شهادة الضمان: صفحة A4 واحدة، علامة مائية بالشعار واسم المحل، واسم المحل بخط كبير. كود العميل (C-0001...) بيظهر عليها وعلى الفاتورة ورسالة واتساب.
- كود العميل: بيتولّد من السيرفر حسب رقم الموبايل (نفس العميل = نفس الكود حتى لو الرقم اتكتب بصيغة تانية).
